## 4. What the dataset cannot tell us (as submitted)

1. Real dust or blur: no dust, haze or sensor degradation is stated, so we must add it.
2. Real sensor noise: the IMU is derived from perfect pose, with no noise unless we add it.
3. IMU and LiDAR rates: not stated.
4. Data licence: not stated. Ask the authors before publishing results or sharing data.
5. Independent heading reference: no magnetometer, sun or polarisation compass is listed.
6. GNSS or spoofing: no GPS signal, so any attack must be simulated by us.
7. Terrain or texture labels: none marks an environment as sandy or low texture.
8. Wheel odometry: not listed for wheeled robots (proprioception is ANYmal only).
9. Sim to real: the authors report no real world validation.

Not checked by us (pages not reachable from our side on 1 November 2026): MIT licence of the toolkit, the file list sizes, the IMU generation method, the LiDAR conflict, the NED frame, the author stated limitations list (our reading of the paper found only a remark that the SLAM evaluation is small scale), and the Hugging Face repository. These stay marked "reported by the audit, not independently verified" until a second author confirms them.

Unresolved conflict: the audit reports the paper version 1 as stating 70 environments and 910 trajectories (226 differential drive, 441 omni). The paper text we opened states 63 and 878 and does not say which version it is. We cannot tell from our side whether this is a version difference or a transcription error. Action: the audit to paste the exact sentence from the arXiv version 1 abstract and the version number of the text we read.

Gaps to close before the audit can be signed off:

1. The IMU file was downloaded but not opened. Opening imu.zip would answer the open question on rate, format and noise directly. Action: report file names, number of rows, timestamp spacing, columns and units.
2. The camera archives for P1003 were not downloaded, so no frame has been looked at. Action: download the two front camera archives, view five frames spread along the trajectory, and record whether the scene is sandy and textured or not.
3. The licence question remains open. Action: do not share or republish any file. A note to the CMU AirLab authors is to be drafted by the lead author.
4. The camera to IMU transform and the NED to body frame convention are not stated, and these are needed for any adapter. Action: find them in the metadata file already downloaded.

Consequences for E01 (proposals, not findings):

1. The IMU has no noise by construction. For a fair B0 we must add a documented noise and bias model, and say so in the protocol.
2. The toolkit needs an NVIDIA GPU stack. The lead author's laptop should download archives directly instead of installing the toolkit.
3. No wheel odometry exists for the differential drive trajectories, so B0 uses visual and inertial input only, as planned.
4. The data licence gap means results can be reported but data files must not be redistributed.
